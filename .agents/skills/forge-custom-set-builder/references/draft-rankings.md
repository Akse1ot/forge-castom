# Ranked-файлы Limited

Проверено по локальным ReadDraftRankings, DraftRankCache, CardRanker, LimitedPlayerAI/BoosterDraftAI и ANKH_EXACT_V1, 02.11.2026. При изменении Forge повторно проверь релевантные методы. Это минимальная стартовая оценка, без обучения и массовых симуляций; отдельный проект Chaos Draft AI не затрагивается.

## Формат и применение Forge

```text
//Rank|Name|Rarity|Set
#1|Actual Forge Name|R|CODE
#2|Another Card I|C|CODE
```

- UTF-8, без BOM и пустых строк до/внутри списка: Reader прекращает чтение на пустой строке. Комментарий начинается `//`. Заключительный перевод строки допустим.
- Четыре поля через `|`: `#позиция`, имя, редкость, код выпуска. Reader отбрасывает первый символ позиции; редкость не участвует в расчёте. Выдавай строго последовательные позиции 1..N без дублей: Reader сам этого не гарантирует, повторное имя перезаписывается.
- Карты ищутся по имени и edition. Имена и суффиксы должны соответствовать Forge; Reader удаляет диакритику. Lookup заменяет ` // ` на пробел, загрузка не заменяет: для такого имени в RNK нужен пробел вместо разделителя; каноническое имя сохрани в отчёте. Проверяй коллизии нормализованных имён штатным Reader.
- Рейтинг Reader = position / максимальная позиция выпуска, меньше лучше. CardRanker преобразует его в `100 - 100 * rating`, отсутствие записи даёт −100. Последняя карта полного списка получает 0. Числовые расстояния между внутренними оценками в RNK не сохраняются.
- CardRanker дополнительно применяет RemAIDecks (−20), штраф закрытых цветов (−50) и динамические DeckHints/DeckNeeds. Limited AI выбирает первую карту отсортированного pack; RNK не заменяет оценку цветов/колоды.
- Обычный файл выпуска использует его настоящий код, устанавливается пользователем в `<Forge resources>/draft/rankings/<code>.rnk`. DraftRankCache требует перезапуска после обновления. Не путай с выбранным отдельным custom ranking: тот читается относительно `res/draft` и ищет edition `CUSTOM`, с дополнительным преобразованием для не-custom карт. Для обычного рейтинга выпуска `CUSTOM` писать нельзя.

## Пул и входные файлы

После завершения карточных скриптов и окончательного editions выгрузи фактический драфтовый пул, учитывая колляцию и включённые sheets. Не считай все строки editions автоматически драфтовыми. Все уникальные доступные карты, репринты и небазовые земли должны присутствовать ровно один раз; повторные печати/арты не создают новый рейтинг. Не включай закомментированные карты, токены и базовые земли, если они не являются оцениваемыми picks. Текущий инструмент исключает Basic Land; если выпуск действительно драфтует специальные basics как picks, сначала отдельно согласуй/адаптируй эту границу, не теряй их молча. ANKH_EXACT_V1 даёт 249 уникальных небазовых карт, включая 22 земли.

`pool.json`: объект с `set_code`, `cards`; каждая карта содержит `name` (Forge), `rarity` (C/U/R/M/S/L), `mana_cost` (например `2 W W`), `types` (Forge Types), `power`, `toughness` (строки или null), `colors` (список W/U/B/R/G), `oracle`, `keywords` (напечатанные K, без префикса K:). Допустимы `mana_value`, `faces` и исходные метаданные/пути/хеши. Для многосторонних карт сохраняй все лица и разбирай их совокупную игровую ценность; эвристика первого лица не является полной оценкой такой карты. При сложной стоимости предпочитай подтверждённый mana_value из Forge.

Реальный адаптер источника/editions зависит от проекта: проверь его результат сравнением с CardEdition.Reader и фактическими booster sheets. Не используй номер как силу. Количество карт не должно быть жёстко задано универсальным генератором.

```powershell
python <Skill>/scripts/build_draft_rankings.py --pool <set>/rankings/pool.json --review <set>/rankings/oracle-review.json --out-dir <set>/rankings --prepare-review
# Заполнить/проверить обязательные REVIEW REQUIRED записи, затем:
python <Skill>/scripts/build_draft_rankings.py --pool <set>/rankings/pool.json --review <set>/rankings/oracle-review.json --out-dir <set>/rankings
```

Шаблон review содержит `name`, `semantic_sha256`, `oracle_grade`, `synergy_bonus`, `roles`, `reason`. Не заполняй оценки по редкости или числу keywords. Изменение имени/стоимости/типов/характеристик/Oracle/лиц инвалидирует review; --prepare-review сохраняет неизменённые разборы, новые/изменённые требует проверить. При изменении состава сначала обновляй pool; не генерируй из устаревшего снимка. Обновляй разборы синергий и неизменённых карт, если изменилась среда. Хеш не способен обнаружить это автоматически.

## Минимальная оценка v1

Итог 0..5 = 25% ограниченной эвристики + 75% содержательной оценки Oracle + бонус синергии 0..0.25. Сортировка по убыванию; равные оценки упорядочиваются по имени, без утверждения превосходства. Редкость читается только для вывода и контрольного сравнения M/R/U/C; номер не используется.

Эвристика: эффективность тела относительно mana value; напечатанные уклонение/боевые способности/защита; функциональные роли interaction, advantage, engine, ramp, fixing, tokens, selection, protection, finisher; штраф дорогой/цветотребовательной стоимости и tapped land. Коэффициенты и компоненты доступны в скрипте и ratings.json, без скрытой модели. Условные способности/токены не считаются безусловными keywords существа.

Oracle-review обязателен для каждой карты: 0 почти неиграбельна, 1 нишевый filler, 2 обычная playable, 3 сильная playable, 4 premium, 5 исключительная бомба. Объясни эффективность, качество ремувала/добора/ресурсов, темп, ограничения целей, повторяемость, суммарную стоимость активаций, drawback, реальную вероятность условий. Для земель оцени фиксацию, tempo и альтернативные режимы. Сильная самостоятельная карта приоритетна; узкая многокарточная комбинация не считается гарантированной. Десятые доли не означают измеренную точность. Список допустимых roles — ROLE_POINTS в скрипте.

## Завершение и проверка

Выходы: `<code>.rnk`, `ratings.md` (все карты и причины, сравнение с редкостью), `ratings.csv`, `ratings.json` (компоненты). Сохрани входы и команду для воспроизводимости. Не заявляй, что автоматический расчёт заменяет содержательную оценку.

Обязательно сверить весь пул, канонические имена/суффиксы, дубли и 1..N, отсутствие пустых строк, finite оценки и актуальность review. Проверить RNK текущим ReadDraftRankings и по возможности несколько паков CardRanker с открытыми/закрытыми цветами. Для проверки внешнего файла можно передать относительный путь от ForgeConstants.DRAFT_DIR; устанавливать файл не требуется. Изолированный тест может подставить Reader в process-local DraftRankCache, не меняя Java движка и файлы ресурсов. Это проверяет подключение оценок, не качество драфта.

При регенерации проверять детерминированность и независимость от редкости/номера. После ручной установки пользователь перезапускает Forge. Для non-draft создание RNK необязательно.
