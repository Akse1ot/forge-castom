# Проектирование и внедрение Java-патчей

**Не запрещай патч ради одной карты.** Граница допустимости — потенциальный объём и риск вмешательства, решение об этом принимает **пользователь**, не Codex.

## До согласования (этапы 2–4)

1. Чётко выпиши недостающую семантику из оригинальных карт; группируй карты общей механики и учти перекрывающиеся зависимости.
2. Проверь актуальную реализацию в нынешнем Forge. Если для понимания нужны целые классы, цепочки обработки объектов и событий — изучи их; экономия токенов не может оправдывать ошибочное понимание.
3. Сравни штатный API, уже существующие локальные кастомные расширения и минимальный новый hook/helper. Не дублируй уже существующий механизм.
4. Предпочитай малые локальные изменения, изолированные селекторы, хелперы, совместимость со штатными картами. Зафиксируй точные места/классы и возможные регрессии. Не подменяй глобальную семантику `Enchanted`, `DamagedBy` и подобных селекторов ради одной карты.
5. Если предварительная оценка указывает на большую перестройку фундаментальных систем — **D**, без подробного проекта и без Java-правок. Для прочих напиши план, объём вмешательства и тесты; не принимай решение о допустимости самостоятельно.

## После отдельного утверждения (этап 6)

- Работать **прямо в текущем локальном репозитории** Forge, без обязательного worktree или общения с remote. Проверить `git status`/сохранённую локальную контрольную точку; не стирать несвязанные изменения.
- Вносить только утверждённые изменения и минимальные необходимые тесты. Если приходится менять архитектуру сверх плана — остановиться и запросить решение.
- Запускать **адресные**, а не исчерпывающие тесты изменённых механизмов; особенно проверить возможный эффект на штатных картах. Убедиться, что Java собирается подходящим локальным способом. `git diff --check`, просмотреть ограниченный diff.
- Сохранять в отчёте изменённые Java-файлы и краткую семантику доступного скриптам API. Не делать `git reset --hard`, `git clean`, `git push/pull`, автоматические коммиты.

Общий аудит отличий локального Forge от upstream **не входит** в этот навык. Результаты внешнего проекта по такому аудиту можно принять как справочную информацию, но навык не должен от них зависеть.
