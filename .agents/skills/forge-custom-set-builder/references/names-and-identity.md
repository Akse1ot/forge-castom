# Идентичность карты, репринты и коллизии имён

**Порядок обязателен: кандидаты → игровая идентичность → репринт/различие/неоднозначность → имя.** Совпадение имени само по себе не доказывает ни репринт, ни необходимость суффикса. Этот алгоритм применяется внутри рабочего процесса Builder и не меняет его область действия.

1. Закрепи свободный Code из четырёх ASCII A–Z по всем локальным editions, case-insensitive; при продолжении не меняй код.
2. Для совпадающего имени ищи кандидатов в штатных скриптах Forge, доступных кастомных карточных каталогах пользователя и уже обработанных картах текущего выпуска; сверяй listings editions. Учитывай регистр Windows и варианты арта. Разные лица одной карты и дополнительные арты не являются новыми игровыми картами.
3. До присвоения суффикса сравни стоимость, основные типы/супертипы/подтипы, P/T, loyalty/defense и другие применимые характеристики, все способности/ограничения, layout и все лица, а также прочие механически значимые свойства. Для официальной карты при необходимости сверяй текущий Oracle и официальные изменения. Используй проверку типов из AGENTS.md § 4.2.1 и явно утверждённые пользовательские трактовки кастомных типов; трактовка кастомного выпуска не становится универсальной заменой.
4. Различай механические изменения и печатное оформление. Арт, художник, flavor, символ выпуска, редкость и номер не создают новую игровую идентичность. Изменённая официальная терминология, напоминания и эквивалентные шаблоны требуют осмысленной проверки, а не простого текстового равенства. Нельзя автоматически стирать скобки или считать похожий текст доказательством идентичности.

## Решения

| Статус | Действие |
|---|---|
| Подтверждённый официальный репринт | Каноническое имя без римского суффикса, существующий штатный скрипт, новая печатная запись editions и отдельный арт выпуска; дублирующий карточный скрипт не создавать. |
| Подтверждённый репринт кастомной карты | Переиспользовать её каноническое имя/реализацию, если надёжно установлена идентичность и проверено, что текущий Forge поддерживает такую печатную запись. Не объединять при сомнении. |
| Другая карта с совпадающим именем | Первый свободный суффикс через пробел I, II, III…; согласовать Name, filename, editions, изображение и необходимые игровые ссылки. Чужую карту не переименовывать. |
| Неоднозначность | needs_review: не назначать суффикс и не объединять автоматически; сохранить источник и конкретный вопрос для согласования. |

Суффиксная схема после подтверждения различия: `Name:Brimstone Mage I`, `Brimstone_Mage_i.txt`, `1 R Brimstone Mage I`. Фактический путь изображения определять текущим `ImageUtil`, а не предположением о full/fullborder или об обязательной цифре 1. У многочастных карт проверять все лица и layout.

## Данные, повторный запуск и проверка

- Для каждого source_id/URL сохраняй отдельно author/original name, canonical name, reprint_status, ссылку на существующую карту/скрипт для репринта, основание suffix_reason для отличающейся карты и решение/подтверждение. Разделяй неизменный снимок источника и производное игровое представление. Имя существующей кастомной реализации может уже иметь суффикс: каноническим является именно оно.
- В name-map включай source ID/URL, original/canonical name, reprint_status, existing_card, script/image paths и edition number; для репринта script_file нового скрипта отсутствует. Резервируй утверждённые имена; не вычисляй их заново на каждом продолжении. Изменение источника/кандидата или исправление прежней ошибки требует явной записи причины, а не молчаливого пересуффиксирования.
- Генератор обязан проверять identity decision **до** создания скрипта и выделения имени. Подтверждённый репринт никогда не превращается снова в `… I` и не получает копию штатного скрипта. При изменившейся идентичности/неподтверждённом кандидате нужна новая проверка.
- Для новой печатной записи отдельно проверить реальный loader/CardDb: тот же существующий CardRules/скрипт, новый set code, авторские rarity/number/artist и собственный image key. Имя файла и art index проверять через ImageUtil; дополнительные арты одной карты могут требовать разных индексов.
- Ошибочный staging-дубликат убирать только после подтверждения новой привязки и проверки допустимости удаления/архивирования; установленные ресурсы не менять. Обновлять все активные mapping/manifests/generators/listings, сохраняя исторические данные явно как архив.
- Адресные проверки: реальный репринт использует каноническое имя и существующий скрипт; другая одноимённая карта получает первый свободный суффикс; неоднозначность не объединяется; повторная обработка сохраняет решения; печатные метаданные и изображение относятся к новому выпуску.
- `Card.named…`, `Name$…` и иные ссылки исправлять только с пониманием конкретной идентичности; не менять автоматически слова в названии/художественном тексте. Нереализованные карты остаются в editions комментариями под уже установленным каноническим/различающим именем.

## Подтверждённый пример, 2026-10-31

В Ankheret официальный Jackal Familiar имеет R, Creature — Jackal, 2/2 и ограничение атаки/блока в одиночку. Подтверждён [официальным Gatherer](https://gatherer.wizards.com/Pages/Card/Details.aspx?multiverseid=191073) и текущим `forge-gui/res/cardsfolder/j/jackal_familiar.txt`. Арт Ankheret и его номер 138 отличаются от Magic 2010, но не создают новую карту: правильны имя Jackal Familiar, штатный скрипт и отдельная запись ANKH. Не использовать этот пример как универсальное соответствие Hound → Jackal; выбор типов кастомного выпуска проверяется отдельно по официальным данным и контексту.
