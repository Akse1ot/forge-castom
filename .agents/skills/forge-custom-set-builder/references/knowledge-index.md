# Индекс накопленных знаний Forge (живой справочник)

Это **не перечень гарантированно действующих API** и не мониторинг upstream. Важные записи по мере работы заноси в небольшие разделы ниже либо в отдельные документы, если тема существенно разрастётся. Старые знания не должны принуждать к старым реализациям после изменений движка.

## Правило обращения

1. Сначала найти полезный предыдущий вывод в соответствующем справочнике.
2. Кратко проверить присутствие релевантных классов/методов/операторов в **текущем локальном** Forge.
3. Если изменились — изучить нужный участок в достаточной глубине (целый класс допустим), обновить именно затронутую запись. Одна необъяснённая ошибка — не основание объявить механизм устаревшим.
4. Сохранять только подтверждённые, **повторно полезные** знания. Не вести лог каждого обычного скрипта, не делать весь каталог движка предметом аудита.

## Шаблон записи

- **Тема:** краткое имя механизма/паттерна.
- **Статус:** `проверено` / `требует актуализации` / `устарело` / `заменено`.
- **Проверено в:** дата, локальная ветка/коммит (если известен), класс/файл/метод, способ проверки.
- **Семантика:** что делает; для каких карт.
- **Ограничения:** границы применения, известные регрессии.
- **Минимальный рабочий пример:** путь к реально существующей карте/тесту (если стабилен) или небольшой фрагмент.
- **Связанные знания:** релевантные записи.

## Нынешние справочники

- `forge-scripting.md` — правила построения способностей.
- `engine-patches.md` — процесс разработки Java-доработок.
- `ai-hints.md` — проверенные отличия Deck-полей.
- `editions.md` — классические/расширенные/недрафтовые выпуски.
- `names-and-identity.md` — конфликтующие имена.
- `sources-and-images.md` — источники и изображения.
- `dwap-lessons.md` — исторический опыт.
- `engine-notes.md` — локально проверенные границы Deck-фильтров, загрузки лиц и имён (30.10.2026).
- `validation.md` — четыре адресных приёма из постоянного DWAP-теста и границы их доказательств.

Схема исторического JSON и отображение полей адаптера — `sources-and-images.md`; план малого пилота и независимость от временных архивов — `first-run.md`.

Новые сведения о конкретных Java-подсистемах можно добавлять в `engine-notes.md` только после проверки актуального кода; новые механики — в `mechanics-notes.md`. Не дублируй полный Java-исходник и не сохраняй всё содержимое аудитов.
