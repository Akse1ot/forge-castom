# Правила Forge: проверяем по текущему репозиторию

Этот документ задаёт **принципы**, а не обещает точный API конкретной версии. Codex обязан сверять синтаксис, параметры и исполнение по локальным исходникам пользователя.

## Источники истины

1. Текст оригинальной карты, подтверждённый URL/экспортом/изображением.
2. Локальные Java-классы, обслуживающие соответствующий способ действия.
3. Проверенные скрипты Forge, желательно того же механизма и текущей ветки.
4. Тесты конкретного поведения. Успех одного теста не переносится автоматически на другую карту.

## Структура

- Проверяй `Name`, `ManaCost`, `Types`, `PT` и другие поля по типу карты. Для существующих скриптов не меняй имя без разрешения.
- Для способностей исследуй поддерживаемые K/S/T/A/R и необходимые `SVar`, `Defined`, `ValidCard`, условия, триггерные данные и рекурсию SubAbility именно в текущем движке.
- Для многочастных карт проверь, как Forge хранит и загружает каждую часть. Общие поля `DeckHas`, `DeckHints`, `DeckNeeds` не должны теряться из-за второго определения.
- Не ставь пустую первую строку. Не добавляй лишние пустые строки; допустимые разделители многочастных/альтернативных карт и DFC сохраняй как требует фактический формат.
- `SVar` сам по себе не означает вопрос или выбор игрока. Проверяй исполняющий параметр.
- При `may`, `up to`, `another`, `each`, `target`, `owner`, `controller`, `combat damage`, `this turn`, `until end of turn`, `when you do` анализируй реальное поведение, не только Oracle.
- Если есть взаимодействие с собственными механиками пользователя (Resonance, Ash of War, Cursed, custom opening-hand actions и др.), проверяй **наличие** и текущую реализацию в локальном коде; не предполагай совместимость автоматически.
- Не изменяй штатную семантику глобальных селекторов ради одной карты. Предлагай локальную, минимально инвазивную реализацию.

## Подсказки для ИИ

`DeckHas`, `DeckHints`, `DeckNeeds` и AI `SVar` — не формальная полнота: указывай только обоснованные категории и синергии. Проверь влияние hints на multi-part, дублирование и возможные перезаписи. Не утверждай, что ИИ хорошо играет карту, пока нет соответствующей проверки.

## Режим доказательств

Для нестандартных операторов в отчёте укажи локальный путь к классу/скрипту-образцу. Когда подтверждения нет — статус `needs_review` или `blocked`, а не синтаксис наугад.
