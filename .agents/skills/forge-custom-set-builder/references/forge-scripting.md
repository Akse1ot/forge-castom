# Правила написания скриптов Forge

**Проверяй против текущих локальных Java-исходников и существующих скриптов.** Ниже не обещание наличия параметров в произвольной версии Forge.

- Прочитай `AGENTS.md` текущего проекта. Выбирай штатные `K`, `S`, `T`, `A`, `R`, `SVar`, `SubAbility`, `ValidCard`, `Defined`, `Condition...` только после подтверждения их обработки в текущем движке. Изучай нужную цепочку Java, если описание не раскрывает семантику.
- Проверяй точные условия: стоимость vs эффект, источник/контроллер/владелец, зоны и ограничения времени, `target` vs `choose`, `may`, `up to`, `when/whenever/if`, длительность, LKI, триггеры и замещение. Не считать строку `Description` реализацией механики.
- Для многочастных карт разбирай обе части и общее состояние (например, Deck-поля и Skill). Следуй **реальным** примерам разделения (`ALTERNATE`, split/DFC/Adventure), не добавляй пустую первую строку. Иначе лишних пустых строк не добавляй.
- Если локальный Forge уже имеет кастомную механику, не делай новый Java-патч. Сначала разбери её настоящий интерфейс. Не меняй глобальное значение старых селекторов; предлагай отдельный `Defined`/selector/helper при необходимости.
- Сопоставляй имена/параметры через `references/names-and-identity.md`. Не замещай значащий Oracle текст ради компенсации нерабочего скрипта; при ошибке источника отдельно фиксируй предположение.
- Токен-скрипты и имена `TokenScript` проверяй на существование и соответствие типу/цвету/P/T/навыкам; изображение токена необязательно для реализации его механики.
- `DeckHas`/`DeckHints`/`DeckNeeds` + AI-SVar — по необходимости, не «для заполнения». Читай `ai-hints.md`.
- Если точная реализация невозможна сейчас, оставь карту незавершённой, занеси в B/C/D или в «текст требует уточнения». Отсутствие механики в **известной документации** ещё не означает её отсутствие в текущем коде.

## Опыт DWAP — только ориентиры для исследования

Среди случаев, где требовалась не просто правка описания: `Cage the Soul` (привязанное по длительности изгнание); `Take up Blades` (цепочка Forge/Attach); `Winter's Tomb` (изменение типа после возврата); `Grave Reckoning` (каждый оппонент); `Snowslide` (перепроверка цели через стек). В других версиях Forge оператор или реализация может поменяться. См. `dwap-lessons.md`.
